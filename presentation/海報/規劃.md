# 展版海報規劃（已與使用者確認，2026-10-08）

## 規定（海報製作規範）
- 海報 1：統一呈現【組別序號（寫「第 115XXX 組」）＋題目名＋專題 logo＋組員＋指導老師】
- 海報 2、海報 3：呈現專題簡介與成果，且四點都要出現在海報上：
  1. Project Purpose：專題動機與目的
  2. Problem Statement：對於重要（嚴重）問題的描述
  3. Approaches：專題方法與程序
  4. End Result：專題成效說明
- 檔案：高解析度、可印刷的 PNG 與 PDF；Logo 及海報中使用之圖檔另附 PNG（本案另附 SVG）
- 命名：`組別序號－海報號碼`（例 `115414－海報1`）、`組別序號－名稱`（例 `115414－Logo`），連接號用全形「－」

- PDF：文字向量、字型內嵌；PNG：300 dpi（檔內寫入 300 dpi）。

## 視覺風格（沿用介紹動畫 v2）
- 背景：`linear-gradient(180deg, #FFFFFF 0%, #FBFCFD 42%, #E6EDF1 74%, #CBD8E0 100%)`，無顆粒、無網格。
- 色票：ink `#16222B`（標題、內文）、deep `#2F4552`、slate `#627D8D`（品牌主色、重點、線條、大數字）、muted `#5B6770`（副標、說明）、success `#2E9E5B`、soft `#EEF2F5`、line `#D3DADF`。
- 字型：Noto Sans TC（全部文字）；IBM Plex Mono 500 只用於櫃門號 A01–A04。
- 品牌名「救「舊」我的書」：「「舊」」三字（含括號）用 slate，字重 700（大標可 900）。
- 元件：白卡＋大圓角（20–28 等比放大）＋淡雙層陰影 `0 1px 0 rgba(98,125,141,.12), 0 16px 36px rgba(22,34,43,.08)`；膠囊 chip；綠勾 cbadge；slate 線條 icon（stroke 1.6、round cap）；引線標註（slate 細線＋白底 slate 描邊圓點）；步驟列（編號圓圈，完成綠色）。
- 3D 書櫃、手機一律標「3D 示意」。
- Logo 使用向量版（取自 `介紹動畫/v2/src/lib/logo.ts`）。

### 海報 2（在電腦螢幕下方）
標題格式：`01 專題動機與目的 Project Purpose`（中英並列）

**01 專題動機與目的 Project Purpose**
- 動機（系統簡介 P1 前言）：學生之間的二手書交易常遇到面交需配合雙方時間、書況描述與實物有落差、預付款後可能遭遇詐騙等問題。
- 目的（系統手冊 1-3，p.6，五項系統目標）：簡化交易流程、打破時空限制、提升使用體驗、促進資源循環、強化交易安全（各附一句說明，取自手冊原文）。

**02 問題描述 Problem Statement**（本專題「二手書籍交易行為與市場需求調查」，498 份有效問卷）
- 面交：43.2%「擔心對方失約或遭遇詐騙」
- 寄送：57.9%「須自行包裝並至超商寄件」
- 期待：51.4%「傾向使用實體儲物櫃」
- 書櫃功能：57.4%「最看重 24 小時自助存取」
- 註：複選題之比例以勾選次數計（只標在真正的複選題上，需依問卷整理檔核對）。
- 來源：問卷整理檔、影片 intro、複評簡報 S7、系統手冊 p.2–5。

**03 專題方法與程序 Approaches（系統概觀）**
- 核心機制：「先驗收、後撥款」（系統簡介 P2、README）
- 交易閉環六步：線上看書況 → 下單付款 → 掃碼存書 → 掃碼取書 → 驗收確認 → 撥款（競賽系統概述 二）
- 七項 AI 服務（複評簡報 S10）：上架輔助、資料補齊、上架審核／個人化推薦、AI 書籍顧問／AI 客服、爭議分析
- 系統架構（複評簡報 S8、影片 system）：Flutter App、ESP32 智慧書櫃 → Cloudflare・NGINX → Node.js（Express／Socket.IO／Prisma ORM）→ MariaDB；外部服務：OpenAI／Google Gemini、Google Books／Open Library、data.taipei、Firebase
- 主視覺：書櫃＋手機（3D 示意）

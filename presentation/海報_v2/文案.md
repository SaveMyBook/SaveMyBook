**03 專題方法與程序　Approaches**

交易閉環（一行）：線上看書況 → 下單付款 → 掃碼存書 → 掃碼取書 → 驗收確認 → 撥款

**① 智慧書櫃**
- 主標：一片 ESP32，控制四扇櫃門
- 硬體標註

| 元件 | 規格 |
|---|---|
| 2.8 吋 TFT 螢幕 | 顯示 QR Code 與數字 |
| ESP32-S3 控制板 | Wi-Fi 連線・HTTPS 同步 |
| 四路繼電器 | 驅動電磁鎖 |
| 12V 電磁鎖 ×4 | 裝於櫃門左側，斷電上鎖 |
| 門磁開關 ×4 | 偵測櫃門是否關閉 |

- 四道驗證：動態 QR Code｜定位必要｜兩位數比對｜裝置憑證・關門回報
- 賣家存書：1 掃描書櫃 QR Code → 2 確認存書項目 → 3 輸入螢幕比對碼 → 4 比對成功，A01 開鎖 → 5 放入書籍並關門 → 6 存書完成，通知買家

**② 驗收與撥款**
- 付款暫管 → 取書關門 → 24 小時驗收 → 撥款至賣家錢包
- 規則：款項由平台暫管，買家確認書況或取書24小時爭議期屆滿後才撥款。

**③ AI 書況與售價**
- 主標：拍張照片，AI 判斷書況與售價
- 輔句：附上判斷依據、建議售價區間與資料來源

**④ AI 上架輔助**
- 主標：ISBN 掃描快速上架
- 流程：掃描 ISBN → 書目自動帶入 → 書況與建議售價 → 上架審核
- 七項 AI 服務：上架輔助｜資料補齊｜上架審核｜個人化推薦｜AI 書籍顧問｜AI 客服｜爭議分析

**系統架構**
Flutter App ／ ESP32-S3 書櫃 → Cloudflare → NGINX → Express API ＋ Socket.IO → MariaDB
外部服務：OpenAI｜Google Books・Open Library｜data.taipei｜Firebase

**04 專題成效　End Result**

| 301 | 1,563 | 2,815 | 7 |
|---|---|---|---|
| API 端點 | 後端測試 | App 測試 | 項 AI 服務 |
| RESTful API | 11 組全數通過 | 全數通過 | 上架到售後 |

- 書櫃實機　螢幕、繼電器與四顆電磁鎖測通；正式韌體已連網並完成配對
- 完整交易流程　上架、付款暫管、存書、取書、撥款與爭議處理皆可實際操作

**頁尾**
讓閒置的書，重新流動。　savemybook.today　［QR → https://savemybook.today/］

## 需確認

1. **AI 供應商名稱寫法不一。** 1013 P9 與官網 L337、L360 只寫 OpenAI；手冊 p.7 與概述 二寫「OpenAI 與 Google Gemini（可切換供應商）」；README L37、L61 寫「DeepSeek / Gemini / OpenAI」；程式碼 `savemybook_api/services/ai/settings.js` L14 預設 `default_provider: 'deepseek'`，L22 上架輔助預設 `provider: 'gemini'`。海報 2 的技術標籤已避開供應商名稱；架構列照 1013 P9 用「OpenAI」。若要完全不出錯，可改用 README L37 的「AI 服務」。
2. **書櫃硬體：自製主控板還是開發板＋繼電器模組。** 1013 P22 標註「自製主控板 Rev A」，但 P31 說 Rev A「已送打樣」（還沒裝上）。韌體 README L13–16 的實機是 ESP32-S3 開發板＋四路繼電器模組，P31 也寫「螢幕、繼電器與四顆電磁鎖測通」。海報 3 若放實機照片，建議用本稿的「ESP32-S3 控制板／四路繼電器」；若放 1013 P22 的 3D 圖，改用「自製主控板 Rev A／平放於頂層，ESP32-S3 主控」。
3. **門磁開關還是微動開關。** 1013 P22 寫「門磁開關 ×4」；韌體 README L23 的實際零件是 MATRIX 微動開關 ×4（用途是門磁）。本稿依 1013 用「門磁開關」。
4. **電源規格不一（本稿沒有用到）。** 1013 P22「12V 電源輸入」、概述 七「12V 5A 電源」；韌體 README L17–18 是 24V 3A 電源經 7812 降到 12V。若要加電源標註，請先確認實機用哪一種。
5. **③ 解法標題字數。** 使用者擬的「拍張照片，AI 判斷書況與售價」約 14 字，超過 12 字上限。海報 2 先用「AI 判斷書況＋建議售價」（1013 P4），原句移到海報 3 當 ③ 主標。
6. **③ 的數字是解法需求，不是問題發生率。** 逾 95% 量的是「看照片有沒有幫助」，不是「書況不符的比例」。問卷沒有書況不符發生率的數字。
7. **④ 問題句的逗號。** 1013 P8 是兩行「有閒置書想清空／卻懶得處理」，中間沒有逗號（已轉圖確認）。10-10 版 pptx 有逗號。照刪字規則不能補逗號，請用斷行。
8. **複選題百分比不能寫成「%的受訪者」。** 57.9%、43.2%、35%、51.4%、30.9% 都是勾選次數占比（分母 605／787／803／566／787），不是人數占比。海報不要在這些數字前後加「受訪者」。手冊 p.3–4 的「35%的受訪者」「51.4%的受訪者」寫法嚴格說不精確，所以不採用。單選題（57.4%、31.1%、逾 95%）沒有這個問題。
9. **六步交易閉環只出現在概述 二（競賽文件）**，1013 簡報沒有。如果要求海報只用 1013 用語，改用官網 L282 的五步，或拿掉這一行。
10. **賣家存書第 6 步**：原句「存書完成，通知買家取書」11 字，本稿刪成「存書完成，通知買家」以符合 10 字上限。
11. **動機句選哪一句。** 主選手冊 1-1（閒置與書價），因為海報 2 的 02 區已列出 ①–④ 的問題。如果想讓動機直接列出問題，用 README L4 刪字版（44 字），但它不含寄送與上架負擔。

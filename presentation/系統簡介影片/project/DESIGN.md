# 系統簡介影片：設計與製作規則（所有段落必須遵守）

使用者已核准的樣張是「賣家上架」段，程式在 `src/tour/s_list.ts`。這是**標準範例**：寫新段落前先讀懂它，風格、節奏、程式寫法都照它做。

使用者給的風格參考是一支 Apple 式的產品宣傳短片（TAIWAN FIMILY 網站 2.0 介紹）。重點如下：
- 背景是白色到淡藍的漸層，全片只用單一品牌色。
- 畫面上方置中放粗體大標，下面一行副標，文案短而口語。
- 3D 手機是主角，會飛入、傾斜、多支錯落、快轉翻面。
- 用「螢幕變暗＋元件浮出」來強調 App 的某一塊。
- 動作必須連續、滑順，有衝擊力。

## 使用者明確否決過的做法（絕對不要再出現）
- 圓圈、光圈、同心圓環、圓環隧道轉場。
- 卡片式 UI 拼湊：白色圓角卡片、左側色條、圓角方塊圖示、膠囊標籤、打勾清單、點陣背景。使用者說這看起來「太 AI」。
- 簡報感的版面，例如左邊一排條列文字、右邊放手機。
- 放大鏡，以及畫面上疊框、疊虛線、連線指向手機。
- **手機和文字重疊**（包含進出場的過程）。
- **放大時連背景一起放大**，包括：
  - 衝進螢幕的轉場；
  - 浮出範圍包含元件周圍的 App 背景；
  - 相鄰的浮出元件互相疊住。
- 卡頓：任何速度或加速度的突變。
- 字色只能用 E（石板藍），已設在 `promo.css` 的 `--blue` 與 `--blue2`，不要自己改顏色。

## 版面
- 畫面 1920×1080。左上角的 logo 由 main.ts 固定顯示，不用處理。
- **標題**：用 `kit4.Title`（預設 y=128，大標 80px，副標 34px），一律放在上方中央，佔 y < 230 的範圍。
- **手機**：放在標題下方，頂端不可高於 y≈250。
  - 參考值：單支置中時 `s ≈ 1.4`、`y ≈ -0.32`（畫面比例座標）。
  - 手機下緣可以延伸到字幕後方，這點使用者已接受。
- **字幕區 y > 930**：所有文字與浮出元件都不得進入（手機機身除外）。
- 中英混排時，中文和英數之間空一格。

## 動作
- 手機、書櫃的姿態一律用 `kit4.glide(t, keys, sigma=0.3)`。它把關鍵姿態連成直線路徑後，與高斯函數做卷積（解析解），結果無限次可微，所以不會卡頓。
  - **不要用** `track`、`easeInOut` 去拼接姿態。
- 數值過渡（浮出程度、亮度等）用 `kit4.soft(t, t0, t1)`（五次平滑）。浮出時可再套 `back()`，帶一點回彈。
- 鏡頭不可以完全靜止。停在重點時，也要給一點點的推近或旋轉，參考 s_list 中相鄰關鍵影格的微小差異。
- 可以用的手法：
  - 從下方升起、左右甩入甩出。
  - 原地快轉一圈：轉到背面（ry = π）時切換畫面，切換時刻設成那一刻，轉場秒數 0.01。
  - 多支手機前後錯落（後面那支 z 為負、s 略小）、由下方仰角升起（rx 為負）。
- 進出場只走畫面下方或左右，不可以從標題區穿過。
- **浮出**：`world.frame.phones[i].pops = [{ id, screen, rect, k, grow?, dy?, dz? }]`，同時把 `glow` 調到約 0.6，讓螢幕其他部分變暗。
  - `rect` 必須是元件**精確的外框**，用 `python3 tools/bounds.py <畫面名> <x> <y>` 從截圖量出來，`x`、`y` 填卡片內一點的 App 邏輯座標。
  - 多個相鄰元件一起浮出時，必須用 `grow`（約 0.12）加上 `dy` 拉開間距，`dz` 錯開深度，寫法照 s_list 的 FIELD_CARDS。
  - **pop 的 id 必須全片唯一**，一律加上段落前綴，例如 `find_warn`。
- 章名：每段開頭（open、end 除外）用 `kit4.ChapterWord(fx, '章名')`。
  - 顯示時間是段落內 0.1 秒到約 1.0 秒，結束後主角才進場。
  - 章名必須和右上角章節名稱一致：系統總覽、賣家上架、買家找書、付款暫管、智慧書櫃、驗收售後、帳號會員、管理後台、技術架構。
- **段落邊界**：
  - 3D 物件只能在段落內 `0 ≤ t ≤ 段落長度` 期間寫入 `world.frame`。
  - 段落結束時，所有物件必須已經完全出畫；下一段的章名在 0.1 秒出現。
  - 出場動作請在最後一句旁白的最後約 0.9 秒內完成，參考 s_list 的 `adm`。
- 音效：用 `cue()`、`fly()`（`src/lib/cues.ts`）。可用的類型見 `audio/sfx.py`，例如 `pop`、`lift`、`swipe`、`whoosh`、`key`、`tap`、`notify`、`unlock`、`door_open`、`door_close`、`success`、`coin_land`。

## 素材
- **App 畫面**：`public/screens/<名稱>.webp`，可用 `ls public/screens` 列出。
  - 這些畫面全部是真實 App 畫面，有兩種來源：Flutter 實際渲染，以及實機截圖（`n_*`，說明見 `assets-src/new_screens/README.md`）。
  - 有 PNG 的原圖在 `assets-src/screens/`。
  - 已量測過的重點區塊在 `src/scenes/story.ts`（R、GUIDE、PICK、WALLET、AFTER、ADMIN_R、KEYPAD、DIGITS）。
  - 逐字輸入的畫面序列在 `src/lib/sequences.json`，用法參考 `frameSteps()`。
- **3D 書櫃**：寫入 `world.frame.cabinet = { pose, kiosk, door?, deposit?, withdraw?, xray? }`。
  - 書櫃螢幕的狀態見 `src/three/textures.ts` 的 Kiosk（`qr|busy|match|opening|open|done`）。
  - 舊版的用法可以參考 `src/scenes/deposit.ts`、`pickup.ts`、`rig.ts`。
- **Logo**：`src/lib/logo.ts` 的 LogoDraw（描線動畫）。品牌名稱與左上角位置見 `src/scenes/brand.ts`。
- 舊版場景 `src/scenes/*.ts` 只能拿來參考 API 和座標，**不可以照抄畫面設計**，因為使用者要的是全新設計。

## 開發與檢查（每段交付前必做，結果要附在回報中）
開發伺服器已經由主控開在 `http://127.0.0.1:5291`，**不要自己再開，也不要關掉它**。

1. `npx tsc --noEmit -p .`：自己的檔案必須零錯誤。
2. `node tools/overlap.mjs <段落起秒> <段落迄秒> 0.05`（絕對秒數），結果必須是「無重疊」。這個檢查會抓：
   - 文字互相重疊；
   - 文字壓到手機；
   - 浮出元件之間重疊；
   - 浮出元件壓到文字；
   - 文字或浮出元件進入字幕區。
3. `node tools/motion.mjs <起秒> <迄秒>`：輸出中 `r*[*]` 與 `p*[0..2]` 的最大 jerk 必須 ≤ 1。`p*[3]` 是角度換算的量測假象，可以忽略。
4. 用 `node tools/still.mjs <scratchpad 資料夾> <秒...>` 每 0.5 秒截一張，再用 `magick montage` 拼成總覽圖，自己用 Read 工具逐張看。檢查項目：
   - 有沒有重疊、穿模、出界、元件糊掉；
   - 畫面是否空洞；
   - 有沒有和使用者否決過的做法相似的地方。
5. 回報內容：
   - 每個畫面上出現的文字及出處；
   - 三項檢查的輸出；
   - 總覽圖的路徑；
   - 自評哪裡還不夠好。

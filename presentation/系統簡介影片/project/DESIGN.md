# 系統簡介影片：設計與製作規則（所有段落必須遵守）

## v3 規則（2026-10-26，NTUB_SIS 宣傳片風格；網址加 `?v3` 時使用，優先於下方各版規則）

規格來源：`scratchpad/web_v3/SPEC.md` 第二節。標準範例是 `src/tour/s_cabinet_v3.ts`（書櫃存書樣片）。數值一律引用 `src/v3/spec.ts` 的 `V3`，不可在場景裡另寫。

### 共用模組（`src/v3/`）
| 模組 | 用途 |
|---|---|
| `spec.ts` | 字級、顏色、安全範圍、浮出與轉場的固定數值 |
| `title.ts` | `TitleV3`：置中兩行標題＋副標，整塊淡入並上移 40px，離場再上移 40px 淡出 |
| `subtitles.ts` | `SubtitleBand`：畫面裡的字幕帶（main.ts 在 `?v3` 時建立一份，全片共用） |
| `backdrop.ts` | `Backdrop`：淡霧藍斜向漸層加兩團緩慢漂移的光暈（main.ts 全片共用一份）；不畫同心圓、圓環或漣漪 |
| `camera.ts` | `CameraPath`、`orbit`、`whip`、`move`、`sequence`：鏡頭與段內轉場；`sectionPans`：段落交界的進出場橫移，距離依 `PANS` 表 |
| `frame.ts` | `fit`：指定物件在畫面上的中心與高度，反推手機或書櫃的世界座標與縮放 |
| `pop.ts` | `lift`（浮出時間，停留不足會報錯）、`preloadSlots`／`slotColor`（空位顏色）、`under`（對話框浮出後原位改顯示遮罩下的頁面）、`float`（完全浮出後的輕微漂浮） |
| `label.ts` | `LabelV3`：物件旁的名稱標籤（36px、字重 600），不畫引線 |
| `kiosk.ts` | `kioskPop`：書櫃螢幕從原位朝鏡頭浮起 |
| `tools/reelcheck.mjs` | 版面檢查（main.ts 的 `__reelCheck`），每 0.1 秒一格 |
| `tools/bounds.mjs` | 段落交界檢查：整格只剩背景的時長、出畫與入畫距交界的時間（校正 PANS 用）、物件在交界才突然消失或閃現；用法 `Q=v3 node tools/bounds.mjs 0.1` |

段落檔為 `src/tour/s_<段落>_v3.ts`（`export default (world, ui, fx) => (t) => void`），main.ts 在網址加 `?v3` 時依檔名動態載入；一段載入失敗只有那段留白。
共用檔（`world.ts`、`main.ts`、`src/v3/*`）只由主控修改，各段不可改。

場景的固定寫法：
- 每格寫 `world.frame.camera = sectionPans(<段內鏡頭>, t, LEN, { sec: SEC })`；背景由 main.ts 統一繪製，段落不寫背景。
- 3D 物件與鏡頭只由目前的段落寫入（main.ts）：交界那一格不會混入上一段的物件。相鄰段落在前後 1 秒仍會被呼叫，只用來更新自己的標題等畫面元件。
- 標題、標籤、點擊、飛行數字等畫面元件每格都要更新（在提早返回之前），它們在段落外會自己隱藏。圖層在段落前後 1 秒就會顯示。
- 物件一律用 `fit` 依畫面位置擺放；段落外（t < 0 或 t > LEN）不寫入 3D 物件。

各段的寫法：先寫時間點（沿用旁白，`onBeat` 對拍點），再定鏡頭（`CameraPath`），再用 `fit` 依畫面位置擺物件，最後登記音效。一段一個檔案（`src/tour/s_<段落>_v3.ts`），共用的東西只放 `src/v3/`。

### 字級與顏色（1080p；4K 輸出整體乘 2）
- 字型：`'PingFang TC', -apple-system, 'Noto Sans TC'`，蘋方排第一。標題元素同時帶 `promo__title` 類別（給 overlap 檢查），必須蓋掉 promo.css 的 `letter-spacing` 與 `font-feature-settings: 'halt'`；'halt' 會把全形「？」換成半形寬度的字形，第一版樣片的問號就是這樣變窄的（v3.css 已處理）。
- 大標 60px、字重 600、行高 1.27、#1D1D1F，兩行置中，第一行上緣 y=44。
- 副標 27px、字重 500、#4D626F，距大標 10px。
- 字幕 32px、字重 500、#1D1D1F，不描邊，只加極淡的白色柔光；單行中心 y=1028。
- 背景 #FFFFFF→#DFE6EA 斜向漸層，加左上、右下兩團 13% 霧藍光暈緩慢漂移；重點色只有霧藍 #627D8D。
- 不使用同心圓、圓環或漣漪（2026-10-26 使用者要求全片移除，連同轉場與片頭片尾）。

### 安全範圍
- 標題區塊下緣約 y=241。手機、書櫃、浮出元件距標題文字至少 40px。
  - 與標題左右重疊的物件，上緣不得高於 y=281。
  - 放在標題左右兩側的物件可以更高。
- 字幕帶 y ≥ 976：手機、書櫃、浮出元件一律不得進入。
  - 因此書櫃一律完整入鏡，高約 650px。
  - 手機約佔畫面高度七成（約 750px）時，要放在標題左側或右側；放在標題正下方時最高約 690px。
- 浮出元件完全浮出時，距畫面邊緣 56px、在標題下方 40px 以下。
- 檢查：`Q=v3 node tools/reelcheck.mjs <起秒> <迄秒> 0.1` 必須「無問題」，再加上 collide 0 筆、overlap、半尺寸逐格人工檢查。

### 浮出
- 每句旁白只浮出一個元素：
  - 手機上的元素用去背元件（照元素邊界與圓角）。
  - 書櫃上的元素是螢幕本身。
- 時間用 `lift(t, t0, t1)`：浮出 0.5 秒，完全浮出至少停 1.5 秒，落回 0.35 秒。
- 手機元件：`grow` 0.15–0.35，再加 `dx`／`dy`（App 邏輯 pt）移到不擋內容的位置；`slot: slotColor(cut)` 在原位留下空位，顏色為周圍六點的中位數，並加內陰影。
- 對話框類的浮出（整個對話框浮起，四周是半透明遮罩）不留單色空位：原位顯示對話框後方的頁面，加上同一層遮罩。先用 `tools/under.py <有對話框的畫面> <同一頁沒有對話框的畫面> <cut>` 產生 `<畫面>_under.webp`，再以 `scr: under(seq(t, steps), k, '<畫面>_under')` 在浮起期間換成它，不設 `slot`（付款段的 `v_pay_done_under`）。
- 書櫃螢幕：`kioskPop(world, k, cam, 書櫃姿態, { toward, left, up, scale })`。
  - 放大 1.6–2.2 倍；`toward` 為往鏡頭靠近的距離，透視會再放大。
  - 預設 `turn` 0.8，保留一點書櫃的角度。
  - 原位改為深灰內凹（#4C545C 加內陰影）。
- 浮出時不壓暗螢幕（`glow` 維持 1）。

### 轉場與鏡頭
- 換鏡頭只移動 3D 鏡頭，不交叉淡化截圖，也不滑動裁切後的畫面。
- 甩鏡（`whip`）0.5 秒：鏡頭原地轉向下一個主體，中段最快；方向性模糊由輸出時 180° 快門（`sh=180`）的動態模糊產生。
- 平移／推移（`move`）0.95 秒：鏡頭與注視點一起移到下一個主體，距離不同時同時推近或拉遠；背景不加任何轉場圖形，動感來自鏡頭移動與 180° 快門的動態模糊。
- 甩鏡與平移的方向要讓高的手機不必橫越標題，也不經過字幕帶。例如舊畫面手機在右側時，鏡頭向左甩，讓它由右側出畫；新的手機若會在途中橫越畫面，就先不顯示，甩鏡後再由畫面外移入。
- 手機換畫面直接切換（`seq` 的 mode 0、時長 0.001），不淡化：淡化中間格會出現兩層字。唯一例外是底下畫面位置完全不變、只有對話框與遮罩出現或消失（付款成功、查詢中轉為已帶入、開啟配對對話框），改用時長 0.12 秒淡化，和 App 對話框出現的速度相近，直接切換則像跳格；對話框換成另一種版面（如輸入配對碼轉為等待連線）仍直接切換。推入（mode 1）、返回（mode 2）、底部面板（mode 3）照 App 的轉場。需要大轉換時，在手機翻到背面時切換。
- 段落交界：`sectionPans` 讓上一段最後 0.9 秒鏡頭往左移（離場加速）、下一段最初 0.9 秒由右側移回（進場減速），交界那一格移動最快，看起來是同一個橫移。移動距離依段落寫在 `camera.ts` 的 `PANS`，由 `tools/bounds.mjs` 印出的出畫／入畫時間反推：上一段主體在交界前約 0.03 秒出畫、下一段在交界後約 0.03 秒入畫，整格只剩背景不超過 0.05 秒。改了段落的擺位或鏡頭，要重跑 bounds 並校正 PANS。
- 片頭與片尾的標誌：淡入 0.5 秒，同時由 0.92 倍輕微放大到原尺寸（`x_open_v3.ts` 的 `markIn`），不彈跳。片頭品牌段的標誌在書櫃出畫途中就開始淡入；片尾的標誌在交界後立刻淡入，左上角標誌提早在交界前收完。
- `whip` 不加滾轉；`whip`／`move` 的緩動用五次平滑（加速度連續）。
- 標題的進出場要避開甩鏡與平移的中段。

### 音效與字幕
- 卡點音效只對應本段畫面上的動作，用 `cue`、`fly`、`TapOn` 在場景檔登記。沒有畫面動作的音效不登記。
- 字幕的拆段與時間沿用 `audio/subs_new.py`；畫面標題與旁白相同的句子不上中文字幕（`audio/subs_hide.json`）。
- 預覽與檢查時，main.ts 的 `SubtitleBand` 把字幕畫在畫面裡（讀 `audio/out/subs.ass`）。
- 輸出成品時以網址參數 `nosub` 算圖，再由 `audio/subs_v3.py` 產生 v3 樣式的 ASS（蘋方 PingFangTC-Medium、#1D1D1F、不描邊、極淡白色柔光，單行中心 y≈1028；中英版中文 y≈1007、英文 y≈1052），由 ffmpeg 燒入。前後沒有相接的字幕在開始前、結束後各淡化 0.12 秒（與預覽的 `SubtitleBand` 相同），同一句拆成兩段時直接換字。中英字幕的英文在 `subs_v3.py` 的 `EN`；蘋方的 ASCII 連字號是較寬的減號造形（ESP32-S3 會像 ESP32–S3），燒入的字幕、`TitleV3`、`LabelV3` 與預覽字幕帶都以 `src/v3/spec.ts` 的 `hyphen()` 把字間的連字號換成 U+2010；SRT 保留 ASCII。
- 成品流程：`cd audio && bash build_v3.sh`（可只做 `audio`、`render <段落…>`、`finish`）。4K 畫面以段落為單位存在 `audio/out/v3seg/`，修改某段後只需重算該段。

## 第二版規則（2026-10-09 定案，優先於下方第一版規則）

第一版全片被評 60 分。第二版的標準範例是 `src/tour/s_list.ts`（賣家上架）與 `src/tour/s_find.ts`（買家找書），成品樣片在 `../樣張/第二版樣片_上架與找書_4K.mp4`。分鏡原則在 `../分鏡v2.md`。

1. **App 畫面一律由 `savemybook_app/tool/video_shots/` 重新產生**，資料用正式站 API（唯讀）的真實書籍、實拍照片與使用者。
   - 不可再用 `public/screens/` 的第一版畫面或示範封面。
   - 輸出到 `public/v2/`：`screens/v_*.webp`、`cuts/*.png`、`cuts.json`、`taps.json`、`sequences.json`。
   - 每段的截圖測試檔另開，例如 `tool/video_shots/pay_test.dart`。
   - 多人同時工作時，執行 `flutter test` 前必須取得鎖：`until mkdir /tmp/smb_video_shots.lock 2>/dev/null; do sleep 5; done`，跑完 `rmdir /tmp/smb_video_shots.lock`。這樣不會同時編譯，json 合併也不會互相覆蓋。跑完用 git 還原 `pubspec.lock`。
2. **浮出元件只用去背元件**：寫成 `{ id, cut: 'cut_xxx', k, grow, dx?, dy?, dz? }`，位置與圓角由 `cuts.json` 自動帶入。
   - 去背元件必須是**不透明的完整元件**，例如整張卡片或整個泡泡。純文字或半透明的元件浮起後，原位的字還在下方，看起來會像兩層字。
   - 驗收：每個元件都要貼在洋紅底上放大 2 倍檢查，並貼回原畫面逐像素比對。
3. **浮出方式（使用者選定「B 為主、A 為輔」）**
   - B：相鄰的一組元件用 `kit5.spread(names, grow, 'col' | 'row')` 往手機右側展開，放大 30–60%；手機同時往左讓位（x 約 −0.27、ry 約 0.13）。
   - A：單一元件、或彼此相隔很遠的元件，原地放大浮出，`grow` 約 0.15。
   - 不可讓相鄰元件在原地同時浮起，會黏在一起。
4. **節奏**
   - 每句旁白只做一件主要的事。
   - 每組元件完全浮出後至少停留 1.2 秒才收回；浮出動畫本身另計 0.5 秒。
   - 時間由該句結尾往回排，寫法照 `s_find.ts`。
   - 換場與浮出對齊拍點 `kit5.onBeat`。小節 `onBar` 只能在小節夠短時使用，有些段落一小節長達 1.7 秒，會把停留時間吃掉。
   - 同一組元件依序浮出，每個間隔半拍。
5. **轉場**：不再用急甩出畫或原地快轉一圈。換頁用 App 內推入（`seq` 的 mode 1）；換手機改成沿同一道弧線接力，或一支退到後方；`glide` 的 sigma 用 0.42。
6. **字幕**：畫面上的文字和某句旁白一字不差時，把該句 id 加進 `audio/subs_hide.json`。
7. **點擊**：用 `kit5.TapOn(ui, phone, 'tap_xxx', t0)`，座標取自 `taps.json`。
8. **檢查**：先跑四項自動檢查（tsc、overlap、collide、motion）。之後再從 4K 縮小的成品影片每 0.5 秒抽一格逐張看，並另外看關鍵畫面的原尺寸。只靠自動檢查不能交付。

- **手機和文字重疊**（包含進出場的過程）。
- **放大時連背景一起放大**，包括：

  - 浮出範圍包含元件周圍的 App 背景；

- 卡頓：任何速度或加速度的突變。
- 字色只能用 E（石板藍），已設在 `promo.css` 的 `--blue` 與 `--blue2`，不要自己改顏色。

## 版面
- 畫面 1920×1080。左上角的 logo 由 main.ts 固定顯示，不用處理。
- **標題**：用 `kit4.Title`（預設 y=128，大標 80px，副標 34px），一律放在上方中央，佔 y < 230 的範圍。
- **手機**：放在標題下方，頂端不可高於 y≈250。
  - 參考值：單支置中時 `s ≈ 1.4`、`y ≈ -0.32`（畫面比例座標）。
  - 手機下緣可以延伸到字幕後方，這點使用者已接受。
- **字幕區 y > 930**：所有文字與浮出元件都不得進入（手機機身除外）。
- 中英混排時，中文和英數之間空一格。

## 動作
- 手機、書櫃的姿態一律用 `kit4.glide(t, keys, sigma=0.3)`。它把關鍵姿態連成直線路徑後，與高斯函數做卷積（解析解），結果無限次可微，所以不會卡頓。
  - 關鍵影格的時間必須**嚴格遞增**。只要有一格時間比前一格早，軌跡就會發散，手機直接飛出畫面。
  - **不要用** `track`、`easeInOut` 去拼接姿態。
- 數值過渡（浮出程度、亮度等）用 `kit4.soft(t, t0, t1)`（五次平滑）。浮出時可再套 `back()`，帶一點回彈。
- 鏡頭不可以完全靜止。停在重點時，也要給一點點的推近或旋轉，參考 s_list 中相鄰關鍵影格的微小差異。
- 可以用的手法：
  - 從下方升起、左右甩入甩出。
  - 原地快轉一圈：轉到背面（ry = π）時切換畫面，切換時刻設成那一刻，轉場秒數 0.01。
  - 多支手機前後錯落（後面那支 z 為負、s 略小）、由下方仰角升起（rx 為負）。
- 進出場只走畫面下方或左右，不可以從標題區穿過。
- **浮出**：`world.frame.phones[i].pops = [{ id, screen, rect, k, grow?, dy?, dz? }]`，同時把 `glow` 調到約 0.6，讓螢幕其他部分變暗。
  - `rect` 必須是元件**精確的外框**，用 `python3 tools/bounds.py <畫面名> <x> <y>` 從截圖量出來，`x`、`y` 填卡片內一點的 App 邏輯座標。
  - 多個相鄰元件一起浮出時，必須用 `grow`（約 0.12）加上 `dy` 拉開間距，`dz` 錯開深度，寫法照 s_list 的 FIELD_CARDS。左右相鄰、間距只有約 10pt 的卡片，`grow` 要降到 0.04 左右，寫法照 s_find 的 REC_CARDS。
  - 浮出元件會往鏡頭抬起，靠近螢幕下緣的元件因透視會往下偏移數十像素，容易進入字幕區。這類元件要把手機整支往上移（頂端仍不可高於 y≈250），或用負的 `dy` 往上抬，寫法照 s_find 的 INPUTS。
  - **pop 的 id 必須全片唯一**，一律加上段落前綴，例如 `find_warn`。
- 章名：每段開頭（open、end 除外）用 `kit4.ChapterWord(fx, '章名')`。
  - 顯示時間是段落內 0.1 秒到約 1.0 秒，結束後主角才進場。
  - 章名必須和右上角章節名稱一致：系統總覽、賣家上架、買家找書、付款暫管、智慧書櫃、驗收售後、帳號會員、管理後台、技術架構。
- **段落邊界**：
  - 3D 物件只能在段落內 `0 ≤ t ≤ 段落長度` 期間寫入 `world.frame`。
  - 段落結束時，所有物件必須已經完全出畫；下一段的章名在 0.1 秒出現。
  - 出場動作請在最後一句旁白的最後約 0.9 秒內完成，參考 s_list 的 `adm`。
- 音效：用 `cue()`、`fly()`（`src/lib/cues.ts`）。可用的類型見 `audio/sfx.py`，例如 `pop`、`lift`、`swipe`、`whoosh`、`key`、`tap`、`notify`、`unlock`、`door_open`、`door_close`、`success`、`coin_land`。

## 開發與檢查（每段交付前必做，結果要附在回報中）
開發伺服器已經由主控開在 `http://127.0.0.1:5291`，**不要自己再開，也不要關掉它**。

1. `npx tsc --noEmit -p .`：自己的檔案必須零錯誤。
2. `node tools/overlap.mjs <段落起秒> <段落迄秒> 0.05`（絕對秒數），結果必須是「無重疊」。這個檢查會抓：
   - 文字互相重疊；
   - 文字壓到手機；
   - 浮出元件之間重疊；
   - 浮出元件壓到文字；
   - 文字或浮出元件進入字幕區。
3. `node tools/motion.mjs <起秒> <迄秒>`：輸出中 `r*[*]` 與 `p*[0..2]` 的最大 jerk 必須 ≤ 1。`p*[3]` 是角度換算的量測假象，可以忽略。

   - 有沒有重疊、穿模、出界、元件糊掉；
   - 畫面是否空洞；
   - 有沒有和使用者否決過的做法相似的地方。
5. 回報內容：
   - 每個畫面上出現的文字及出處；
   - 三項檢查的輸出；
